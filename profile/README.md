<h2>一、方案之前：先把三个数写下来</h2>
<p>账号数决定出口下限，操作小时决定线路占用时长，峰值并发决定你需不需要排队机制。三个数里最容易估错的是并发——很多人报的是「平均同时在线」，而风控事件几乎都发生在峰值。</p>
<h3>账号数要按「在用」算，不按「拥有」算</h3>
<p>沉睡号不占出口，但一旦启用就要有一条干净的线等着。务实做法是：在用账号数配等量出口，另留百分之十的冗余给临时启用的号。</p>
<h3>峰值并发用日志统计，别凭感觉</h3>
<p>把最近两周的登录日志导出，按分钟聚合，看同一时刻最多有几个号在操作。这个数通常比团队自己估的高出三到五成。</p>

<h2>二、清单第一组：出口到底要不要独享</h2>
<p>独享不是身份象征，是一道成本题。判断标准只有一条：这条出口上跑的业务，出问题时会不会互相牵连。会，就独享；不会，共享也能用。</p>
<h3>判断线：同一出口上的账号能否承受同时失效</h3>
<p>能承受，说明这些号本来就是同一批测试号或同一业务线，共享可接受。不能承受，比如每条线背后是不同的店铺主体，就必须拆开，因为一次处置会带走整条线。</p>
<h3>独享的真实成本不只是月租</h3>
<p>按目前市场行情，静态独享住宅出口月费大致在六十到两百元一条，具体看地区与带宽，仅供参考。真正的大头是闲置成本：买十条只用三条，等于七条在空转。</p>

<h2>三、清单第二组：一个账号对几条线</h2>
<p>正确答案是「一条主用，一条备用，备用不常开」。很多人理解成两条轮着用，结果账号的登录地区一天变两次，反而更可疑。</p>
<h3>主用线要长期不动</h3>
<p>同一条地址连续服务三个月以上，登录轨迹才会形成稳定画像。频繁更换等于每次都在重新建立信任，成本比省下的那点月租高得多。</p>
<h3>备用线的定位是「接管」，不是「分流」</h3>
<p>备用线平时只做连通性探测，不承载登录。主用线故障时整体切过去，切完就固定下来，不要来回切。切换动作本身要记录时间和原因，方便事后复盘。</p>

<h2>四、清单第三组：分组怎么切</h2>
<p>分组的目的不是好看，是让「一条线出事」的影响面可控。切法有两种，选一种坚持用，别今天按地区、明天按人。</p>
<h3>按地区切：适合投放国家分散的团队</h3>
<p>一个地区一组，组内出口同属一国，运营、素材、支付资料都跟着地区走。好处是资料一致性容易保证，坏处是地区内账号多时，单组冗余压力大。</p>
<h3>按业务线切：适合多店铺多主体的团队</h3>
<p>一个店铺主体一组，组内出口可以跨地区但要与服务地区匹配。好处是主体之间彻底隔离，坏处是出口数量需求翻倍，成本上升明显。</p>

<h2>五、清单第四组：权限与责任怎么定</h2>
<p>方案落不了地，八成卡在权限上。谁改配置、谁审批、谁在故障时拍板，必须写清楚，否则出事时所有人都在等别人。</p>
<h3>配置权限收到一个人手里</h3>
<p>出口的增删改只留一个管理员，运营只拿「使用」权限不开「配置」权限。改配置要留记录：谁、什么时候、改了什么、为什么。</p>
<h3>故障响应给出明确时限</h3>
<p>约定一个响应窗口，比如工作时间内半小时确认、四小时内切换备用。没有时限的应急预案等于没有预案，真出事时全组都在群里问。</p>

<h2>常见问答</h2>
<h3>只有三个号，需要买独享吗？</h3>
<p>答：看这三个号背后的主体。如果是同一个店铺，共享一条也够；如果是三个独立主体，建议拆开，处置风险的成本远高于三条线的月租。</p>
<h3>备用线长期不开，会不会浪费？</h3>
<p>答：把它当保险看。可以只保留最低配置做探测，月费压到几十元，仅供参考。真正需要它的时候，现买现配往往来不及。</p>
<h3>分组能不能按运营人员来切？</h3>
<p>答：不建议作为主维度。人员会变动，一变就要重配。真要按人切，也先在地区或业务线分组之上再叠一层，别让人的变动影响出口结构。</p>
<h3>出口数量算下来超预算，先砍哪部分？</h3>
<p>答：先砍闲置和冗余过高的部分，再考虑把非核心业务换成共享出口。核心投放号的出口不要动，那是整个方案里最不该省的一块。</p>
